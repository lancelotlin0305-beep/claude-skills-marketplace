# 獨立評審檢核(產後 QA,另開乾淨 session)

產製者自評有確認偏誤——「交付前檢核」的人工項由產圖的同一個上下文執行,常流於形式(自己改的字自己看不出漏)。因此**成品交付前,交由一個沒有產製過程記憶的獨立評審 session 評分檢核**:Claude Code 以 subagent(乾淨上下文)執行;Claude.ai 或其他環境則另開新對話,只貼下列材料。

**獨立性鐵則**:評審只拿「評審材料」,**不得**接收產製過程的敘述、討論或辯解;評審不重跑產圖、不動手修,只判定與開單。

## 評審材料(產製端負責備齊)

1. 成品 PNG(視覺檢核主體)與 SVG(供字級/結構抽驗)
2. 內容 JSON(content.json)
3. **原始資料/逐字稿**(內容忠實的比對基準——沒有它評審無從驗 A 項,缺了就退件)
4. 判準文件:本檔 + `references/style-spec.md`(§2/§3.1/§6/§11 為主)
5. 第 3 級另附:素材目錄與 `prompts.json`

## 評分維度(六項,各 0–5 分,滿分 30)

| 維度 | 檢核內容 | 主要判準 |
|---|---|---|
| **A 內容忠實** | 圖上每段文字與原始資料**逐字**比對:無遺漏、無增寫、無改寫;數字/單位/標籤對應正確 | SKILL 三原則、§6.3 |
| **B 文字可讀性** | 抽出 SVG 全部 font-size,換算佔畫布高 %,對照 §6.1 該頁面模式錨定表(偏離 ≤10%);最小字 ≥ 下限;主要資訊落在內文級以上 | §6.1、§6.2、§6.4 |
| **C 版面結構** | 無溢出、無重疊、無元素相黏;留白合理(§3.1 決策樹);對齊一致;單圖單訊息、三段敘事、F/Z 動線 | §3.1、§11 |
| **D 素材品質**(L3;無素材時本項改評插圖四件套) | 無殘留背景色/毛邊/誤蝕;**無亂碼文字**(短術語須拼字正確);光源一致左上;全圖素材複雜度一致;顯示尺寸 ≥40px | asset-generation §5、§13 |
| **E 圖文呼應** | 素材是否對應**該卡的訊息**(關係與狀態,不只是類別名詞);同時守住「插圖不載資訊——拿掉素材,資訊仍完整」 | SKILL 三原則、§5 |
| **F 色彩與數據語彙** | 輪色/概念綁定正確;「規劃中/預留」用灰時鐘不佔彩色;文字區淺色、深色底白字對比 ≥4.5:1;數值帶單位、關鍵數字放大;不只靠顏色 | §1、§2、§7、§11.4 |

**字級抽驗指令**(B 項用,對 SVG 執行):統計 `font-size="…"` 出現的所有值與次數,除以畫布高換算 %,對照 §6.1。

## Blocking 缺陷(任一存在即 FAIL,不看總分)

- 數字錯誤、文案與原始資料不符、標籤錯置(A)
- 文字被裁切、互相重疊、超出容器(C)
- 素材含亂碼/拼錯文字(D)
- 大面積殘留背景色(D)

## 判定與回報

**通過門檻:無 blocking 缺陷,且總分 ≥ 24/30,且無單項 < 3。**

評審以 JSON 回報(產製端據此回修):

```json
{
  "verdict": "PASS | FAIL",
  "scores": { "A_內容忠實": 5, "B_文字可讀性": 5, "C_版面結構": 4, "D_素材品質": 4, "E_圖文呼應": 4, "F_色彩語彙": 5 },
  "total": 27,
  "blocking": [],
  "issues": [
    { "dim": "D", "severity": "minor | major | blocking", "where": "卡3素材", "what": "缺陷描述", "fix": "建議修法" }
  ],
  "summary": "一句話總評"
}
```

## 產製端的收發規則

- **FAIL** → 依 issues 逐項回修 → **重送評審**(材料重新備齊,不附辯解);同一缺陷連續兩輪未修好 → 停下來,升級回報使用者。
- **PASS** → 交付,並把評審 JSON 附在交付說明(分數與 minor issues 讓使用者知情)。
- 使用者明確要求「快速出圖/不用檢核」時可跳過本步,**交付說明須註記未經獨立評審**。
- 評審發現的**可通用化缺陷**,依 SKILL「迭代」節寫回對應層(規則進 references、數量進 tokens、失敗模式進 validator),不是只修這一張圖。
