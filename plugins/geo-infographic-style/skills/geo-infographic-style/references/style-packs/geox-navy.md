## 2. 字級——以「佔畫布高度的百分比」定義

> **這一節是踩過坑改出來的,不要退回絕對 px 思維。** `style-spec.md §6` 的字級表是為「自適應單張圖表」(寬 1600–1720、高度隨內容延展、當文件看)訂的;**16:9 簡報頁高度鎖死 1080 且整頁縮放到螢幕或投影**,有意義的單位是**字高佔畫布高的比例**,不是 px。把 §6 的 px 直接搬過來,實測全組字級只有目標的 67–83%,主標最嚴重(67%)。另注意 §6 的「內文 ≥ 16px」是**下限不是目標**,當成目標用會讓整組往下限塌陷。

| 用途 | 佔畫布高 | 1920×1080 | 字重 |
|---|---|---|---|
| 主標 | **5.2%** | 56 | 900 |
| 結論帶 | **3.5%** | 38 | 800 |
| 導言句 | **3.0%** | 32 | 800 |
| 卡標題 | **2.4%** | 26 | 800 |
| 深色磚代號 | **2.2%** | 24 | 800 |
| 內文 / 能力帶 / 深色列 | **2.0%** | 22 | 500–700 |
| 副標 / 卡內副行 | **1.9%** | 20 | 500 |
| 膠囊標籤 | **1.9%** | 20–21 | 700 |
| 大數字 | **6.5%** | 70 | 900(單位 30/700 緊接) |
| 註腳 / 頁碼 | **1.4%** | 15 | 400 |

**換到其他畫布**:一律用百分比重算,不要沿用 px。例如 A4 直式(1240×1754)主標 = 1754 × 5.2% ≈ 91;16:9 但輸出 1280×720 則主標 = 37。

字型:`Noto Sans TC, Microsoft JhengHei, Noto Sans CJK TC`。全圖最小字為註腳的 1.4%,內容區最小 1.9%。

**驗收方式**:輸出 PNG 後量幾處代表性文字的字身高(CJK 字身 ≈ 字級 × 0.88),換算佔畫布高 %,與上表比對;偏離 10% 以上就是整組字級跑掉,不要只調那一行。

## 3. 素材風格鎖(這是本 pack 最關鍵的一段)

本風格的 3D 素材有五個固定特徵,缺一件就會看起來「不是同一批」:

1. **深海軍藍主體**(`#0E2A5C`–`#1B4F9C`),而非預設風格的 matte white / desaturated
2. **青色邊緣輝光** `#29C5F6`——沿物件輪廓與凹槽發光
3. **霧面不透**(看起來像玻璃、實際不透光)——這是能乾淨去背的前提
4. **鏡面地板倒影** + 物件下方發光圓形平台
5. **左上主光**、等角或 3/4 俯視

### 固定尾句(取代 style-spec / asset_prompts.json 的預設尾句)

```
deep navy blue body (#0E2A5C to #1B4F9C) with luminous cyan edge lighting (#29C5F6),
matte OPAQUE frosted finish (looks like glass but fully opaque, NOT see-through, NOT transparent),
resting on a glowing circular platform with a soft mirror floor reflection,
isometric three-quarter view, key light from the upper left,
premium corporate 3D product-visualization quality, sharp clean edges,
single isolated object centered on a solid pure magenta #FF00FF chroma-key background,
no checkerboard, no gradient background, no scenery.
Strictly no text, no letters, no numbers, no logos, no watermarks.
```

### 換色規則
卡片專色不是藍時,把第一句的 `deep navy blue body (#0E2A5C to #1B4F9C)` 換成對應色,**輝光一律維持青色 `#29C5F6` 不換**——輝光是全份的統一語言,換了就散掉:

| 卡色 | 主體描述 |
|---|---|
| 藍 | `deep navy blue body (#0E2A5C to #1B4F9C)` |
| 綠 | `deep emerald green body (#0B5E42 to #17A673)` |
| 橘 | `deep amber orange body (#8A3E0C to #ED7D31)` |
| 紫 | `deep violet body (#3D1F6B to #7C4DBC)` |
| 青綠 | `deep teal body (#08494A to #12908F)` |
| 紅 | `deep crimson body (#6E1610 to #C0392B)` |

### 與 gen_assets.js 的搭配
`scripts/asset_prompts.geox.json` 的每一則 prompt **已內含完整 GEOX 尾句**(含 `product-visualization quality` 與洋紅底指令),因此 `gen_assets.js` 的 `withTail()` 不會再補預設尾句——這是刻意的,避免兩套風格描述打架。洋紅底指令重複出現(腳本另有 `CHROMA` 常數)無害;保留它是為了 **Prompt 交接模式**——使用者手動貼進 Gemini 時,那段指令必須在 prompt 裡。

### 去背
一律 `scripts/chroma_key.js`(自動偵測洋紅底)。**輝光邊緣容易被挖掉**——`--tol` 調低到 45–55、`--alpha` 調到 12–16 保住輝光的半透明外緣。

### 尺寸紀律
- 每頁 3D 件 ≤ 8 件
- 顯示尺寸 < 40px 的位置**不放 3D 件**,改 SVG 線圖示徽章
- 同頁所有 3D 件輝光強度一致

## 4. 概念—顏色綁定(本專案 canonical)

製造業營運 AI 代理案的五模組,**整份簡報固定用這組**:

| 模組 | 色 |
|---|---|
| 訂單智慧預測 | 藍 |
| 採購成本最佳化 | 橘 |
| 動態接單定價 | 綠 |
| 企業 KM 知識家 | 紫 |
| 智能客服代理人 | 青綠 |

> **來源簡報存在不一致**:p.13 的五張模組卡用的是 藍/綠/紫/橘/青,與 p.14、p.15、p.17 的 藍/橘/綠/紫/青 對不上。上表取多數頁的版本為 canonical;**重製時應統一,不要沿用 p.13 的排法**。

其他固定綁定:`巨鷗DataHub` = 橘膠囊 + 藍主體;`AI決策中心` = 藍;`資安/治理` = 綠盾;`AS-IS` = 灰階;`TO-BE` = 全彩。

## 5. 本 pack 的專屬元件

> 尺寸為 16:9 / 1920×1080 基準值;換模式依 `style-spec.md §10.1` 換算。**凡標「內容驅動」者不得寫死**(§3.1)。

| 元件 | 規格 |
|---|---|
| **發光匯流曲線** | 貝茲曲線,`#3FC8F5` 2.6px + `glow` filter;起點吸附 hub 台座下緣、終點吸附卡頂,兩端各置 r=4.5 圓點;多條並行時彼此淨距 ≥ 14 |
| **發光平台** | 橢圓 rx:ry ≈ 6.5:1,青色 radial 由中心 0.55 透明度向外散;上疊 2 圈同心橢圓描邊 `#29C5F6` opacity 0.30／0.20。**平台先畫、元件壓在上面**(層序畫反會蓋住磚底) |
| **多層實體台座**(hub 專用) | 三層由大而小疊:發光底(rx 212、ry 34)→ 下台(rx 180、ry 28、厚 12)→ 上台(rx 146、ry 24、厚 10)。每層 = 上層面橢圓 `xTierTop` + 側壁路徑 `xTierSide`(較暗以做出厚度)+ 青色描邊 opacity 0.55。**扁平單一橢圓不夠**——原簡報的台座有明確體積,少了它整支圓柱像浮空 |
| **貼標膠囊**(如 `巨鷗DataHub`) | **刻意壓在被貼物上緣**(底緣落在圓柱頂橢圓的中線),故**畫在圓柱之後**。與被貼物的重疊是設計語彙,**不適用 §3.1 的 ≥12 淨距**;但與被貼物**內部**元件(如第一條膠囊列)仍須保持淨距 ≥12 |
| **DataHub 圓柱** | 上下橢圓(ry = rx × 0.215)+ 柱身五段漸層 `xCylBody`,左右緣加青色輝光豎線;柱頂橢圓上緣與上方膠囊淨距 ≥ 12。**柱半徑 = 內嵌膠囊寬 ÷ 0.78**(由內容反推,不可先定半徑) |
| **圓柱內膠囊列**(內容驅動) | 寬 = `內距24 + 圓形圖示徽42 + 間距16 + 最長標籤寬 + 內距24`,約佔柱寬 **86%**;高 58、**列距僅 8**(約膠囊高 14%)、圓角 16(非全圓角);堆疊總高 = 柱身 − 上下各 14;圖示為球面圓徽 r=21 + 白線圖示 24,標籤 2.4%(26/700)<br>⚠ 列距是踩過的坑:原為 16(佔膠囊高 30%)、膠囊只佔柱寬 77% → 柱身看起來空且鬆。**原簡報三條膠囊幾乎相連**,間隙一大整支柱子就散掉 |
| **深色系統磚**(內容驅動) | 高 176、r=16 `xTile` 漸層 + 1.5px 青輝光內框 + 頂部 `xGloss` 反光;白線圖示 80 置上、白字代號 2.2%(24/800) 置下。**寬由「圖示 80 或代號寬 + 左右內距」取大者決定**,不得用「區塊寬 ÷ 磚數」 |
| **chevron 箭頭** | 長 44、桿高 16、頭寬 30;專色三段漸層 + `hdr` 投影;走欄間 50px 通道 |
| **結論帶徽章** | r=24 球面徽章,白線圖示 28;徽章 + 結論句視為一個區塊在帶內**置中** |
| **標題右側裝飾** | 柔光圓(r 54–96、`#DCE9FB`–`#E7F1FD`、opacity 0.55)+ 電路紋(`#A9C4E8` 2px)+ 節點圓點(r=4)+ 點陣;僅填標題右方空白,不載資訊、不與內容重疊 |

## 6. 與預設風格的切換

`SKILL.md` 工作流程第 1 步(確認豐富度)之後加問一句:**「用預設風格還是 GEOX 深藍風?」**。選 GEOX 時:

- 讀本檔 + `../deck-anatomy.md`
- defs 用 `assets/defs.geox.svg`(不是 `defs.svg`)
- 素材 prompt 用 `scripts/asset_prompts.geox.json`
- 交付前檢核加三項:①概念—顏色綁定跨頁一致 ②所有 3D 件輝光同強度 ③結論帶高亮詞一頁只用一種顏色
