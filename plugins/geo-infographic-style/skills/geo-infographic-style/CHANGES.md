## v20260812.01:修正 inject_defs 產出無法解析的 SVG

`scripts/inject_defs.js` 抽取 base defs 時用 `/<defs>([\s\S]*?)<\/defs>/`,而 `assets/defs.svg`
的檔頭註解裡就寫著字面的 defs 標籤 → 非貪婪比對從**註解內**那個標籤起算,把註解殘段與
`<svg>` 開標籤一併吃進注入內容,產出的 SVG 無法解析(Chromium 顯示 XML 錯誤頁)。

此路徑是 SKILL.md 工作流程第 5 步明文推薦的用法,屬已發布缺陷。與上一輪在
`gen_hub_flow.js` 踩到的是同一 root cause(註解含字面標籤),當時只修了該檔、未回頭
檢查同源的 shipped 腳本。

- `inject_defs.js`:先 `replace(/<!--[\s\S]*?-->/g,'')` 剝註解再抽取;另加防呆——抽出內容
  若含 `<svg` 開標籤即報錯退出,避免同類問題再次靜默產出壞檔。
- `assets/defs.svg`:檔頭註解改寫並加註「本註解不得出現字面 defs 標籤」。
- 驗證:注入後可正常渲染、重跑冪等(第二次回報「無需注入」)。

## v20260811.02:第十二輪(規則體檢——字級錨定與容器尺寸兩大缺陷)

pilot 對照實測發現兩個**規則層**缺陷(不是實作沒遵守,是規則本身有洞),據此全面體檢並修正。

**缺陷一:字級用絕對 px 定義,未依頁面模式錨定**
- 症狀:把 `§6` 的字級表(為「自適應單張圖表」訂)原封搬進 16:9 簡報頁,實測整組字級只有應有大小的 **67–83%**,主標最嚴重(3.89% vs 應有 5.84%)。
- `§6` 改寫為 **6.1–6.4 四節**:字級表拆成**三組獨立錨定**——自適應=絕對 px、16:9=佔畫布高 %、A4=實體 pt,明令不可互用。
- **修正實質錯誤**:舊版「A4 主標降為 34/900、其餘字級不變」的 16px 內文 = **7.7pt**,遠低於印刷可讀下限;A4 改為 pt 錨定(內文 10.5pt ≈ 22px,低於 10pt 即不合格)。
- 新增 `§6.2`「下限不是目標」——「內文 ≥16px」被當成目標用是整組字級塌陷的第二成因。
- `§6.3` **移除「降一級字級」**:塞不下改為「重新斷行 → 縮短文案 → 拆圖」;為了塞下而降級會使字級系統失效。
- 新增 `§6.4` 驗收方式:量字身高(CJK ≈ 字級 × 0.88)換算比對,偏離 10% 以上是整組跑掉、不要只調那一行。
- 新增 `§10.1`「基準畫布與換模式的換算」:所有絕對 px 以 16:9/1920×1080 為基準;字級依模式獨立錨定、間距圓角圖示依畫布高等比縮放(A4 ×1.62)、陰影描邊虛線不縮放。補上 `§10`(定義三種畫布)與 `§6`(只給一組 px)之間缺失的接口。

**缺陷二:`§3.1` 只規範「卡」,未涵蓋其他容器**
- 症狀:hub 內膠囊寫成「寬 = 圓柱半徑 × 1.66 = 219」,最長標籤內容只有 142 → 右側固定空 35%。**未違反任何現行規則**——規則沒管到膠囊。
- `§3.1` 首條改為「**容器尺寸貼合內容(適用所有容器)**」,明列卡/膠囊/深色磚/清單列/表格 cell/圓柱內列,並**明令禁止由外層反推**(÷欄數、×半徑、÷項數)。
- 例外收斂為三類並各自定義門檻:①等寬欄(取最小欄寬)②分佈帶(帶內項目仍內容驅動,整帶門檻 55%)③頁面級帶(標題/結論/註腳,不套門檻)。
- **填充率門檻 55% → 75%**:55% 等於明文允許容器 45% 是空的,是「容器導向尺寸」的後門。

**新增 `scripts/page_modes.js`——字級與間距係數的程式唯一出處**
- 三模式表(adaptive / 16x9 / a4)含 `type`(字級)、`pct`/`pt`(錨定來源)、`k`(間距係數);生成器一律 `require` 取值,不得自行寫死。
