# 資訊圖表繪製(統一風格)

以固定視覺語言把任何結構化資料繪成簡報可讀的資訊圖表。三原則:**一個群組一張卡、一個專色**(顏色即身分);**全圖淺色**(白底,大面積只用淺色漸層,深色僅限標題列、膠囊、徽章、文字、邊框等小元素);**文字載資訊、插圖做質感**(文案逐字忠於原始資料,插圖拿掉後資訊仍完整)。

## 工作流程

1. **確認豐富度等級**:使用者已指定(「用第 N 級畫」)則直接採用;未指定時**先詢問**——1 線框/2 立體/3 素材場景,附情境建議:草稿 1、簡報內容頁 2、封面/重點頁 3(規格 §13)。
2. **判斷版型**:依資料結構對應下表。
3. **讀取規格**:繪製前必讀 `references/style-spec.md`(全部規則的唯一出處:色彩、立體、元件、連接、插圖、字級、數據語彙、KPI 列、版型細則、頁面模式、易讀原則、裝飾層);第 3 級另讀 `references/asset-generation.md`。
4. **先文後框**:逐卡斷行(全形 19–21 字/行、填滿行寬),量出最寬行推得卡寬與卡高;再依用途選頁面模式定畫布——預設自適應(寬 1600–1720)、簡報單頁 16:9(1920×1080)、報告文件 A4 直式(1240×1754),超載一律拆圖不縮字(規格 §10)。
5. **素材取得(拆卡後才做;選到第 3 級或要求擬真素材時,不可跳步)**:**此時每卡的素材需求已明確**(step 4 已拆出卡片)。依 `references/asset-generation.md`——先選路徑(單物件去背/場景式/OpenAI 真透明),再:
   Q1 有素材來源?(本地目錄／對話上傳)→ 有則驗收後嵌入;
   Q2 沒有 → 問是否用 **AI 產圖**?不要則退回 1–3 級或以 SVG 現繪四件套插圖補位;
   Q3 要 → 選供應商(**預設 Gemini**,亦支援 OpenAI)→ **確認環境**(Node/Playwright/Chromium、對應金鑰;金鑰只從環境變數讀,**嚴禁寫進 skill**)→ 環境不 OK 先**引導安裝/設定**再繼續 → 開元素需求單 → `scripts/gen_assets.js`(單物件)或 `gen_scene.js`(場景)產圖(重試退避)→ 去背(`chroma_key.js` 通用純色,自動偵測背景)→ **同時留存素材 PNG 與所用 prompt(prompts.json)** → 驗收(無毛邊/殘背/亂碼文字;簡短術語如 AI/KPI 可留但須拼對)。
6. **繪製 SVG**:單一檔案;**版型有對應生成器時優先改其資料重用**(見上方版型判斷區);defs 取用 `assets/defs.svg` 的漸層/濾鏡/symbol——可用 `node scripts/inject_defs.js 圖.svg` 自動注入(冪等、只補缺的 id),免人肉整段複製、避免漏貼或貼到舊版;重複元素用 `<use>`;第 3 級素材以 `<image>` 嵌入(規格 §5,素材自帶光影不疊 SVG 投影)。
7. **轉檔**:`node scripts/render.js 圖.svg` 產出 2 倍解析度 PNG。
8. **自檢**:逐項核對下方檢核清單,不過就修正重轉。
9. **交付/嵌入**:單獨繪圖時交付 PNG+SVG;在簡報/proposal 流程中則將 PNG 嵌入該頁,SVG 一併附上供後續修改。

## 版型判斷

| 資料結構 | 版型 | 佈局 |
|---|---|---|
| 一個核心 + 多個關係群組 | 中心輻射 | 核心卡(淺色)置中,群組卡分列左右,虛線相連 |
| 一個主體 + 3–8 個並列面向 | 環形放射 | 核心圓置中,類別沿環排列,說明卡放射於外圈 |
| 有先後順序的階段 | 流程 | 上升軸線(預設)/山形折線/箭頭鏈;共通基礎層以全寬淺色橫帶壓底 |
| 首尾相接的循環流程 | 循環 | 節點沿圓周排列,主色弧線箭頭順時針串接 |
| 並列分類/層級橫帶 | 分組並列 | 全寬橫帶逐層堆疊,或卡片網格;不畫連接線 |
| 主從/上下階層 | 階層 | 金字塔(3–5 層)或樹狀(直角連線) |
| 空間/場域主題 + 多點說明 | 標註 | 中央情境示意 + 編號圓徽 + 引線 + 說明卡 |
| 2–3 方案對照 | 比較 | 等寬卡並排,項目逐列對齊 |
| 統計/佔比/問卷數據 | 數據 | 人形比例圖、百分比橫條、單位方塊、圓餅/甜甜圈(規格 §7) |

數據語彙(§7)與 KPI 大數字列(§8)可與**任何版型**疊加(如環形+KPI、卡內迷你趨勢);各版型細則見規格 §9。

**對不上任何列 / 混合結構時**:先問「這份資料的主關係是什麼?」取**最主要**的一種對應主版型,次要關係用疊加語彙表達(如主體為並列分類但含先後 → 分組並列為骨幹、以 §4 箭頭標流向);仍無法歸類就**拆成多張單一訊息圖**(§11),不要硬塞進不合的版型或自創版式。

每卡項目 2–5 條,超過就拆卡;敘述型內容保持段落,不硬轉清單。

**參考生成器(有對應時優先改其資料重用,不要從零手繪)**:角色/中心輻射 → `scripts/gen_role.js`;流程/roadmap → `gen_blueprint.js`(平行卡)、`gen_blueprint2.js`(階梯成長);其餘版型手繪。素材:單物件去背 → `gen_assets.js`;整組呼應文字的場景 → `gen_scene.js`(見 asset-generation 決策表)。

## 強制規則(違反即重做)

- **一致性**:同圖同層級元素 = 同版式——卡片等寬、間距相等、內距行距相同;標題列一律「左側徽章 + 標題 + 灰色說明」靠左排。群組差異用顏色表達,不用版面結構表達。
- **留白**:卡寬由內容決定;右內距 ≤ 左內距;文字右緣與卡框間不得超過一個字寬空白;末行 < 1/3 行寬時重新斷行。
- **淺色**:禁止深色大面積底色;任何色塊不得單色平塗,一律漸層(+陰影)。
- **字級**:簡報模式,內文最小 16px、全圖最小字 14.5px(膠囊)。
- **狀態語意**:預留/後續年度項目 = 虛線框 + 灰色時鐘 + 灰字、不打勾;圖底附圖例。
- **內容忠實**:文案逐字沿用原始資料,不增刪、不改寫(僅統一標點);資料中沒有的關係不畫。重繪既有圖表前,先逐項清點原圖所有標籤**與所有連接線(起訖對象、方向、數量)**,產出後逐項回對確認無漏、無擅自增寫、無擅自改接;雙語資料須雙語呈現。內容點不足時以圖示補位,不得湊字(規格 §3)。
- **數據呈現**:統計/佔比資料依規格 §7 的數據語彙與輪色規則呈現。
- **易讀**:遵守規格 §11 三原則(單圖單訊息、直標於圖上、數字帶單位)。
- **連接**:依規格 §4 連接語彙(含 ≥ 6px 淨空與落點規則、箭頭色規)。

## 交付前檢核

細節規則見 `references/style-spec.md` 對應節次,此處只列驗收點。**硬性紅線每張必掃;品質項依本張用到的版型/元素抽測**(沒用到的項略過,如純數據圖不必掃 hub-spoke)。

**硬性紅線(任一不過 = 重做):**
- [ ] **內容忠實**:文案逐字一致、無遺漏、無擅自增寫;雙語成對;重繪已逐項回對原圖標籤與連接關係(起訖、方向)
- [ ] **卡寬/留白**:governing 卡右內距 16–40px、短卡「內容佔寬 ÷ 卡寬」≥ 55%、無溢出無固定寬大留白(§3.1)
- [ ] **間距達標**:子元件距卡框 ≥ 12px、並排膠囊 ≥ 20px、標題距子元件 ≥ 14px、流程節點 ≥ 40px(§3.1、§4)
- [ ] **淺色**:無深色大面積底、任何色塊皆漸層(§2)
- [ ] **字級 ≥ 下限**:內文 ≥ 16px、全圖最小 14.5px(§6)
- [ ] **零重疊**:箭頭/連線與卡片零重疊、迴圈線走空檔、標籤不壓卡(§4)

**品質項:**
- [ ] 同層級同版式、等寬等距;群組差異只用顏色不用結構(§一致性)
- [ ] 立體四件套完整:主卡雙層陰影+厚度邊、深色列三段漸層、子卡/列/徽章各級投影;插圖光源一致左上(§2、§5)
- [ ] **帶素材的卡用圖文並置(§14)**:主圖區 35% + 右清單 65%、左右鏡像;素材未塞右上角造成清單列半空;清單列豁免前提成立(§3.1)
- [ ] **中心輻射版型**:中央帶由連線/KPI/核心卡佔用,非僅裝飾填空;核心卡維持淺色(§2);場景素材落地共用地平線(§14、§12)
- [ ] **三級同構**:1–3 級版面骨架一致,只主圖區與裝飾/場景豐富度遞增(§13)
- [ ] 預留 = 虛線+時鐘+灰字、底部有圖例(§3)
- [ ] 數據/易讀:輪色正確、數值直標帶單位、關鍵數字放大、未達成=中性灰、單圖單訊息(§7、§11)
- [ ] 頁面模式正確(自適應/16:9/A4);內容超載已拆圖而非縮字(§10)
- [ ] 豐富度等級=使用者確認等級;第 3 級素材取自素材庫或經同意的 AI 產圖,**整張圖未交生成模型重繪、承載資訊文字由 SVG 負責**(素材可留拼對的簡短術語;§13、§5)
- [ ] 第 3 級走 AI 產圖時:已依序詢問素材來源→是否產圖→供應商→確認環境;素材與所用 prompt 已留存(prompts.json);**金鑰未寫入任何 skill 檔或圖檔**(asset-generation.md)

## 迭代

使用者的修改回饋若可通用化(新的排版規則、色彩偏好),應建議寫回本 skill 的規格檔並重新打包,讓下一次產圖直接受益。
