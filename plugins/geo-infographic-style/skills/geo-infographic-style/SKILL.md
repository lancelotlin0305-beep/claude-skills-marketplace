# 資訊圖表繪製(排版引擎)

以固定視覺語言把結構化文字排版成簡報可讀的資訊圖表。三原則:**一個群組一張卡、一個專色**(顏色即身分);**文字區淺色、素材可搶眼**(承載文字的表面用白底/淺漸層,素材與插圖可深色飽和發光——style-spec §2 表面分類);**文字載資訊、插圖做質感**(文案逐字忠於原始資料,插圖拿掉後資訊仍完整)。

> **本 skill 是排版引擎,不是手繪。** 版面座標由引擎依內容量測後求解、由 validator 驗收,**不得手寫座標、不得寫死字級**。若現有模板都不適用,做法是**新增模板**(見 `references/engine.md`),不是回頭手繪 SVG。

## 工作流程(5 步)

1. **確認畫布與風格**
   - **頁面模式**(決定字級錨定,三組不可互用,style-spec §6.1):自適應單張圖 / 16:9 簡報內頁 / A4 直式報告。
   - **豐富度等級**:未指定先問——1 線框 / 2 立體 / 3 素材場景(草稿 1、簡報內容頁 2、封面重點頁 3,§13)。
   - **風格**:預設八色風格;使用者說「GEOX 風格 / 深藍發光風」或接續同一份簡報時改套 `references/style-packs/geox-navy.md`。

2. **把內容整理成 JSON**——每頁一個檔,欄位見所選模板檔頭。文案**逐字取自原始資料**,不擅自增刪。
   - **有逐頁製作規格 .md 時,先用解析器抽,不要看著圖片手抄**:
     ```
     node scripts/parse_spec.js <spec.md> --list          # 列出所有頁與建議模板
     node scripts/parse_spec.js <spec.md> --out=./content # 全部輸出 <page>.raw.json
     ```
     它抽出主標題、次標題、頁型、頁碼與「頁面完整可見資訊」的巢狀清單,並建議模板。
     **最後一哩(把 groups 對應到模板欄位)仍需人工判斷**,解析器不會猜。
     > 實測價值:手抄圖片會漏內容。同一頁規格明列 5 個資料來源、5 條 DataHub 能力,
     > 交付的圖只畫了 4 個與 3 條——**圖本身就沒照規格做**。以規格為準才抓得到。
   - 長文字**不必手動斷行**,引擎會自動斷(短標籤走平衡斷行、英數代號詞不切斷);要精準控制才用 `lines` 覆寫。
   - 群組配色優先用**概念綁定**(`concept` 欄位,跨頁同概念同色);未綁定則依序輪色。

3. **選模板**——依下方「意圖 → 結構」表挑;`build.js` 也會依各模板的 `accepts()` 自動判定。

4. **產圖**
   ```
   node scripts/build.js <content.json> <out.svg> [--template=id] [--mode=16x9] [--palette=geox-navy]
                                                  [--level=3 --assets=./geo-assets]
   node scripts/render.js <out.svg>          # 出 2 倍解析度 PNG
   ```
   `build.js` 會跑 validator;**任何錯誤即中止、不產出**。錯誤訊息會指出溢出量與建議動作(拆頁、減少項目、縮短文案)。

   **第 3 級素材**:內容 JSON 的元素加 `"asset": "G04_forecast-chart"`(對應 `<assets目錄>/G04_forecast-chart.png`,去背透明 PNG)。
   找得到就以 `<image>` 嵌入並**不再疊 SVG 投影與地面橢圓**(素材自帶光影,§5);**找不到會警告並自動退回 SVG 徽章**,不會靜默留白。
   素材顯示尺寸低於 40px、或單頁超過 8 件時另有警告(deck-anatomy L3)。素材產製流程見 `references/asset-generation.md`。

5. **交付**——單獨繪圖交付 PNG + SVG;在簡報/proposal 流程中把 PNG 嵌入該頁、SVG 一併附上。第 3 級素材流程見 `references/asset-generation.md`。

繪製前必讀 `references/style-spec.md`(色彩、立體、元件、連接、插圖、字級、數據語彙、版型細則、頁面模式、易讀原則、裝飾層的**唯一出處**);**寫或改模板前必讀 `references/engine.md`**;產簡報內頁另讀 `references/deck-anatomy.md`;第 3 級另讀 `references/asset-generation.md`。

## 版型:意圖 → 結構

先判斷資料的**主要溝通意圖**,再對應結構。混合結構取**最主要**一種為骨幹,次要關係用疊加語彙表達;對不上就**拆成多張單一訊息圖**(§11),不硬塞。

| 溝通意圖 | 主版型 | 模板 |
|---|---|---|
| **呈現關係/資料流** | 來源 → 中央 hub → 輸出群 | `hub-flow` ✅ |
| **呈現分類/並列** | 並列多欄卡(可配前言卡與底部權重帶) | `columns` ✅ |
| **比較差異** | 比較表 / Venn | 待建 |
| **呈現時序/演變** | 流程 / 時間軸 | 待建 |
| **呈現流程/步驟** | 橫向分段流程 / 循環 | 待建 |
| **呈現結構/層級** | 樹狀 WBS / 中心輻射 / 環形放射 | 待建 |
| **呈現佔比/數據** | KPI 卡列 / 人形圖 / 橫條 / 甜甜圈(§7) | 待建 |
| **呈現空間/地理** | 地圖輪廓 + 編號圓徽 + 引線說明卡(§9) | 待建 |

**閱讀骨架**:整張圖依「引子→核心→結論」安排,重要元素順 F/Z 視線動線放(§11.5–11.6)。每卡項目 2–5 條,超過就拆卡;敘述型內容保持段落,不硬轉清單。

## 架構(四層,不可跨層寫死)

| 層 | 檔案 | 負責 |
|---|---|---|
| 權杖 | `tokens.json` / `scripts/tokens.js` | 所有「數量」:三模式字級、色盤、幾何、陰影、門檻、頁面框架;另含文字量測與自動斷行 |
| 引擎 | `scripts/engine.js` | Box 幾何、網格/分佈/堆疊求解、繪製原語、頁面裝飾、**Validator** |
| 圖示 | `scripts/icons.js` | 共用線稿圖示庫(查不到回傳中性幾何形並警告,不靜默留白) |
| 模板 | `templates/*.js` | 只宣告「有哪些帶、每帶有哪些項」,**不寫座標** |

**鐵則**:模板不得自行寫死字級、色票、間距——一律 `require('../scripts/tokens')` 取值。違反時 validator 多半抓不到,但下次換畫布或換色盤就會壞。

> `scripts/gen_*.js` 是**已凍結的舊生成器**(移至 `scripts/legacy/`),僅供對照參考,不再新增或修改。素材工具 `gen_assets.js` / `gen_scene.js` / `chroma_key.js` 不受影響,仍為第 3 級的正式路徑。

## 交付前檢核

**引擎已自動驗收的項目**(validator,不過即中止):容器溢出、子元件淨距、等寬欄群組填充率、垂直填充率(下方大片留白)、字級下限、元素重疊、圖示缺件。

**仍須人工確認**(引擎驗不到的):

- [ ] **內容忠實**:文案逐字一致、無遺漏、無擅自增寫;雙語成對;重繪已逐項回對原圖標籤與連接關係(起訖、方向)
- [ ] **概念—顏色綁定跨頁一致**(deck-anatomy §4);群組差異只用顏色不用結構
- [ ] **淺色(文字區)**:承載文字的表面無深色大面積平塗;深色重點卡文字白字且對比 ≥ 4.5:1(§2)
- [ ] **立體四件套**:主卡雙層陰影+厚度邊、深色列三段漸層、各級投影;插圖光源一致左上(§2、§5)
- [ ] **三級同構**:1–3 級版面骨架一致,只主圖區與裝飾豐富度遞增(§13)
- [ ] 數據/易讀:輪色正確、數值直標帶單位、關鍵數字放大、未達成=中性灰;單圖單訊息、三段敘事、F/Z 動線(§7、§11)
- [ ] 頁面模式正確;內容超載已拆圖非縮字(§10)
- [ ] 第 3 級素材取自素材庫或經同意的 AI 產圖(含 Prompt 交接),**整張圖未交生成模型重繪、承載資訊文字由 SVG 負責**(§13、§5)
- [ ] 走 AI 產圖時:已依序詢問來源→是否產圖→能否外呼→(供應商/交接);素材與 prompt 已留存;**金鑰未寫入任何檔案**

## 迭代

使用者的修改回饋若可通用化,依性質寫回對應層——**數量**進 `tokens.json`、**判準與為什麼**進 `references/*.md`、**新版型**開新模板、**新的失敗模式**進 validator。修好一個坑就補一條檢查,讓同類問題不會再靜默發生。
