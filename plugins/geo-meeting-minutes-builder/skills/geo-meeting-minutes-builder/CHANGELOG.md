## 20260804.01 — 首版

建立 skill,涵蓋:

- **三種模式**:A 逐字稿 / B 無逐字稿(手寫摘要+參考資料) / C 跨會議更新
- **兩種會議類型**:對外會議(啟動、需求訪談、確認、驗收)、內部會議(技術 / 知識提升),支援混合
- **產出**:整理後逐字稿 MD(模式 A)、會議記錄 MD、待釐清清單 MD、版本記錄表
- **防幻覺鐵則**:來源標註強制、決議 / 待辦 / 待議三分法與降級原則、期限絕對日期化、
  講者對應信心標註、逐字稿與手寫摘要衝突不自行裁決
- **跨會議追蹤**:待辦 ID 專案內連號、進度回顧表、「未提及」誠實標記、逾期分析、決議變更歷史保留
- **下游交接**:流程草稿 → `geo-bpmn-flow-builder`;需求訪談內容 → `geo-rfp-work-breakdown`(皆需使用者確認,不自動接續)
- **能力邊界**:明確聲明無法讀音訊 / 影像檔,提供外部轉錄工具指引

### 已知限制

- 音檔 / 影片必須先由外部工具轉錄
- 講者對應仰賴出席者名單品質;名單不齊時只能保留匿名代號
- 模式 B 的來源粒度只能到「摘要第幾點」,無法回溯原話

## 20260804.04 — 知識萃取獨立成檔並改為加選項

### 1. 知識萃取移出會議記錄,獨立為 HTML 檔

- 新增 `assets/knowledge-extraction-template.html` —— 單一檔案,**無任何外部資源請求**
  (無 CDN、無外部字型),因為知識檔常在離線或內網環境開啟
- 新增 `references/knowledge-html-spec.md` —— 設計 token、版面結構、兩張 SVG 的計算方式、
  互動與列印規格
- 兩份會議記錄模板的知識萃取節縮為**一行指標**(「未產製」或指向 HTML 檔名),
  讓半年後看記錄的人知道有沒有這份東西
- 新增檔名 `YYYYMMDD_<會議名>_知識萃取_v<n>.html`

### 2. 改為交付會議記錄後才詢問的加選項

- 使用者**一開始就提**知識萃取 / 知識傳承 / 技能傳承 → 直接產製
- **未提及** → 先交付會議記錄,再問一句;得到肯定答覆才做
- **本場沒有值得留存的知識點時連問都不要問**,照實說明即可 ——
  否則使用者每次都要拒絕一遍
- 明訂不得「先做好放著等他要」:那會拖慢會議記錄的交付,
  而會議記錄才是使用者當下真正需要的東西
- 流程從 7 步改為 8 步,第 7 步為「交付並詢問」、第 8 步為條件執行

### 3. SVG 呈現

- **知識分布時間軸**(簽名元素):知識點落在會議時間軸的哪個位置,
  回答「精華集中在哪一段」這個對安排下次會議節奏有實際幫助的問題。
  模式 B 無時間戳時**整塊省略**,不用假座標硬畫
- **分類分布堆疊條**:各分類卡片數佔比,數量為 0 的分類不畫空槽

### 4. 互動與限閱

- 分類 chip 多選篩選,同步調整時間軸標記不透明度
- **🔒 一鍵隱藏限閱內容**,供簡報 / 螢幕分享時臨時使用(預設顯示)
- 列印樣式:展開所有被篩掉的卡片、頁首自動加註含限閱內容警語

### 5. 一致性處理

- 萃取過程發現的缺漏**回寫進會議記錄的待釐清清單**並推進會議記錄版本;
  知識檔只列摘要並註明「權威清單在會議記錄裡」——
  避免兩份文件各有一半待辦,使用者不知道要看哪份
- 交付前檢核拆為 A(會議記錄,每次必過)與 B(知識萃取,僅產製時過)
- 跨會議模式下,本次未要求知識萃取時,前次知識檔維持原狀,
  不為了「保持同步」而自作主張產製
