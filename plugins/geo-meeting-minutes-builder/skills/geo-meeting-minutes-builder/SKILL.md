# 會議記錄產製(輸入 → 逐字稿 → 會議記錄)

預設交付:**整理後逐字稿 MD**、**會議記錄 MD**(待釐清清單為其中一節)、**版本記錄表**。
**知識萃取為獨立 HTML 檔,是交付會議記錄後才詢問的加選項** —— 除非使用者一開始就要求。
方法細節在 `references/`,**動手前先讀對應檔**。

## 最高原則

**可追溯、不加料、不擅自裁決。**
會議記錄的價值來自「可以拿去對質」。寧可標 `未指定 ⚠️` 並進待釐清清單,
也不要為了讓文件好看而補上一個看似合理、實際沒人講過的負責人或期限。

## 能力邊界(先講清楚,不要浪費使用者時間)

**本 skill 不直接轉錄音訊影像檔**(.mp3 / .wav / .m4a / .mp4 / .mov 等)。
使用者上傳這類檔案時:依 `references/input-intake.md`「音檔/影片的轉錄」段,
**轉交 `geo-transcribe-minutes` skill 轉錄**(雲端 API 或本地離線引擎,機密錄音可不出機器),
取得帶時間戳的逐字稿後以模式 A 接手;或說明「沒有逐字稿也能做」(走模式 B),讓使用者選。
**不要假裝聽得到,也不要跳過轉交選項直接叫使用者自己想辦法。**

分流:單場交接錄音只要**一頁式敘事型**技術傳承 HTML(SOP/眉角/Q&A)時,
`geo-transcribe-minutes` 的 handover 模式即可;本 skill 的知識萃取做的是
**卡片化、跨會議累積、含限閱管理**的知識庫,兩者不同產品。

可讀:文字逐字稿(txt / md / docx / srt / vtt / csv)、PDF、簡報 `.pptx`、圖片(手寫筆記照片、簡報截圖)、試算表。

## 模式判定與前置輸入(缺則先索取,不足不產出)

| 模式 | 觸發條件 | 前置輸入 | 產出逐字稿 MD? |
| --- | --- | --- | --- |
| **A 逐字稿模式** | 有外部工具產出的轉錄檔 | 轉錄檔 + 出席者名單 | ✅ 產 |
| **B 無逐字稿模式** | 只有手寫摘要 / 簡報 / 參考資料 | 手寫摘要(必要)+ 其他佐證 | ❌ 不產,且全文標註來源等級 |
| **C 跨會議更新** | 使用者帶入前次會議記錄 | 前次會議記錄 MD + 本次輸入(A 或 B) | 依 A / B |

**出席者名單(姓名 / 單位 / 職稱)在模式 A 是必要輸入**,沒有就無法把 Speaker 1/2/3 對回真人 ——
先索取,不要自己編派角色。名單真的拿不到時,保留 `發言者A` 這類匿名代號並全文標註,不猜。

## 會議類型(決定會議記錄的章節結構)

先自動研判,**產出前用一句話向使用者確認**,不要默默選定:

- **對外會議** — 啟動會議、需求訪談、確認 / 驗收會議。重心在決議、客戶疑問、雙方待辦與待提供文件。
  套 `references/external-meeting.md` + `assets/minutes-external-template.md`。
- **內部會議** — 技術 / 知識提升、內部專案會議。重心在知識萃取、關鍵對話、簡報對照、流程整理。
  套 `references/internal-meeting.md` + `assets/minutes-internal-template.md`。
- **混合** — 兩種內容都有時,兩份章節都出,不要硬塞進單一結構。

**知識萃取適用於所有類型,不是內部會議專屬。** 對外會議中客戶講的產業慣例、法規限制、
歷史包袱,錯過就沒了,價值往往高於內部技術分享。但它是**加選項**,不預設產製 ——
時機與規則見 `references/knowledge-extraction.md`。

## 流程(各步細節見對應檔)

1. **收輸入、判模式與類型** — `references/input-intake.md`。含術語表索取、敏感資訊處理、會議基本資料確認。
2. **整理逐字稿(僅模式 A)** — `references/transcript-cleanup.md`。校正 ASR 錯字、講者對應、保留時間戳,
   套 `assets/transcript-template.md`。**講者對應不確定一律標推測與信心,不得寫死。**
3. **萃取結構化內容** — 通用判定鐵則見 `references/extraction-rules.md`(決議 / 待辦 / 待議三分法、
   期限絕對日期化、來源標註),再依會議類型讀 `external-meeting.md` 或 `internal-meeting.md`。
4. **跨會議比對(僅模式 C)** — `references/cross-meeting.md`,產出「前次待辦進度回顧」置於會議記錄最前;
   知識點 ID 延續、既有卡片補充或修正。
5. **收集疑義** — 寫進會議記錄的「待釐清清單」節(非獨立檔);模式 C 時累加更新、關閉已解決項。
6. **自我檢核** — 依 `references/extraction-rules.md`「交付前檢核 A」逐條過,有缺失先補正再交付。
7. **交付並詢問** — 產出存輸出資料夾(使用者指定;未指定則與輸入檔同層),逐檔列出交付。
   若本場有值得留存的知識點,**在此問一句是否要加產知識萃取 HTML**(措辭見 `knowledge-extraction.md` §1);
   沒有就不要問。**問完即停,等使用者回覆。**
8. **知識萃取(僅在使用者要求時)** — 依 `references/knowledge-extraction.md` 萃取內容、
   `references/knowledge-html-spec.md` 產製 HTML,套 `assets/knowledge-extraction-template.html`。
   完成後**回寫待釐清項目**進會議記錄並推進版本(見 `knowledge-extraction.md` §9),
   然後交付檔案。**做完即停。**

## 鐵則

- **每一條決議 / 待辦 / 待議都要有來源標註**:模式 A 標時間戳 `[01:23:45]`,模式 B 標 `[手寫摘要 p.2]`
  或 `[簡報 p.7]`。標不出來源的內容代表是自己推的 —— 刪掉,或改列待釐清。
- **三分法不可壓縮**:明確拍板才是「決議」;有人認領才是「待辦」;討論過但沒結論的一律進「待議」。
  不確定屬哪一類時,往下降級(決議→待議),不往上升。
- **不得自行裁決衝突**:逐字稿與手寫摘要打架時,產「差異對照表」交使用者裁決。
  預設 **手寫摘要 = 重點指引(代表使用者當下認定的重要性)、逐字稿 = 事實依據**,兩者皆保留。
- **期限一律絕對日期**:以會議日期換算「下週三」「月底前」,並在括號保留原話。換算不出來就標 `未指定 ⚠️`。
- **一次做完一輪即停**,`present_files` 後等使用者回饋,不自動接續下一場會議或自動改版。
- **知識萃取不預設產製**:先交付會議記錄再問;觸發時機、詢問措辭與
  「沒知識點連問都不問」「不先做好放著」「寧缺勿濫」的完整規則,
  以 `references/knowledge-extraction.md` §1、§4 為**唯一權威**,不在他處重述。
- **流程性內容轉交**:會中談到可畫成流程圖的內容,先在會議記錄產「流程草稿(文字步驟)」,
  並主動詢問是否轉交 `geo-bpmn-flow-builder` skill;**不在本 skill 內直接畫 BPMN**。
- **需求訪談內容轉交**:對外需求訪談會議產出後,主動詢問是否轉交 `geo-rfp-work-breakdown` 做二次拆解。
- **敏感資訊**:報價、成本、薪資、人事評價、個資,依 `input-intake.md`「敏感資訊」段處理,
  預設在會議記錄中標記並詢問是否另產限閱版,**不擅自刪除也不擅自外流**。
  知識萃取的 `ACC`(對象脈絡)卡片一律 🔒,產對外版時整段移除(見 `knowledge-extraction.md` §5)。

## 產出檔名規則

存於輸出資料夾(使用者指定;未指定則與輸入檔同層),同一場會議共用前綴:

```
YYYYMMDD_<會議名>_逐字稿_v<n>.md          # 模式 A 才產
YYYYMMDD_<會議名>_會議記錄_v<n>.md         # 含待釐清清單節
YYYYMMDD_<會議名>_會議記錄_對外版_v<n>.md  # 使用者要求才產,移除 🔒 段落
YYYYMMDD_<會議名>_知識萃取_v<n>.html       # 加選項,使用者要求才產
YYYYMMDD_<會議名>_版本記錄.md              # 累加,不覆蓋歷史列
```

版本記錄套 `assets/change-log-template.md`,每次改版增列,舊版檔案保留不刪。
