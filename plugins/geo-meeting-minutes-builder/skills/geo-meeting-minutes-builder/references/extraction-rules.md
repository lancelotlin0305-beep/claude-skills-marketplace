# 萃取鐵則(兩種會議類型共用)

這份是防幻覺的核心。**對外 / 內部會議都必須遵守。**

## 1. 三分法:決議 / 待辦 / 待議

判定順序:先問「有沒有拍板」,再問「有沒有人認領」。

| 類別 | 成立條件 | 典型語言 |
| --- | --- | --- |
| **決議事項** | 有明確結論,且在場有決策權者未反對 | 「就這樣定了」「OK 那我們照 A 案」「不做了」 |
| **待辦事項** | 有具體動作 + 有人認領(或被指派且未拒絕) | 「我下週給你」「這個我來處理」 |
| **待議事項** | 討論過但沒結論,或結論待外部條件 | 「再看看」「等客戶回覆」「下次再談」 |

**降級原則**:不確定屬哪一類時,一律往「待議」降。
把待議寫成決議會造成實質損害(有人以為拍板了就去執行);
把決議寫成待議只是多一次確認,成本低得多。

**特別小心這幾種偽決議**
- 「應該可以吧」「我覺得應該沒問題」→ 待議,不是決議
- 提案者自問自答、其他人沉默 → 待議,並標「無明確回應」
- 「原則上同意,細節再討論」→ 拆成兩條:原則決議 + 細節待議
- 主持人總結時說的話,若與現場討論不符 → 兩者並列,標差異

## 2. 決議事項的三種狀態

不是二分:

| 狀態 | 意義 | 必填 |
| --- | --- | --- |
| ✅ **執行** | 拍板要做 | 決議內容、生效範圍 |
| ❌ **不執行** | 拍板不做 | 決議內容、**不執行理由**、提出者 |
| ⏸️ **延後決議** | 明確說晚點再定 | 待決事項、重啟條件(等什麼) |

**「不執行」的理由是必填欄位。** 沒有理由的否決,三個月後一定有人再提一次同樣的事,
然後又花半小時重新討論。理由記不到就標 `理由未記錄 ⚠️` 並進待釐清清單。

**變更類決議**用前後對照寫:

```
| 項目 | 變更前 | 變更後 | 影響範圍 |
| --- | --- | --- | --- |
| 報表匯出格式 | 僅 PDF | PDF + Excel | 前端匯出模組、後端報表服務 |
```

影響範圍推不出來就留 `待評估`,**不要憑技術直覺編**。

## 3. 待辦事項的欄位

固定欄位,一欄都不能省:

| 欄位 | 規則 |
| --- | --- |
| ID | `A-01`、`A-02` 流水號;模式 C 沿用專案連號 |
| 事項 | 動詞開頭的具體動作,不寫「討論 XX」這種無法判定完成的敘述 |
| 負責人 | 姓名。無人認領 → `未指派 ⚠️` + 進待釐清清單 |
| 協辦 | 沒有就留 `—` |
| 期限 | **絕對日期** `YYYY-MM-DD`。無 → `未指定 ⚠️` + 進待釐清清單 |
| 來源 | 時間戳或摘要頁碼 |
| 狀態 | 新增 / 進行中 / 已完成 / 逾期 / 已取消(模式 C 更新) |
| 相依 | 需先完成的其他 ID,沒有留 `—` |

### 期限絕對日期化

以**會議日期**為基準換算,括號保留原話:

- 「下週三」+ 會議日 2026-08-04(週二)→ `2026-08-12(原話:下週三)`
- 「月底前」→ `2026-08-31(原話:月底前)`
- 「兩週內」→ `2026-08-18(原話:兩週內)`
- 「盡快」「有空就做」→ `未指定 ⚠️(原話:盡快)` —— **這不是期限**

跨週定義有歧義時(「下週三」在週五講可能指 5 天後或 12 天後),
換算後標 `⚠️ 換算可能有歧義`,並進待釐清清單。

### 「討論 XX」不是待辦

待辦必須是可判定完成的動作。把模糊事項改寫成可驗收的形式:

- ✗ 討論資料庫方案 → ✓ 產出資料庫選型比較表並於下次會議提出
- ✗ 追一下客戶 → ✓ 以 email 向客戶確認驗收時程,並回報結果

改寫時**只把動作講明確,不加碼範圍**。原話沒說要做比較表就不能寫比較表 ——
這種情況改標 `事項描述不明確 ⚠️` 進待釐清清單,請使用者補齊。

## 4. 來源標註

每一條決議 / 待辦 / 待議 / 重點摘要都要有:

- 模式 A:`[00:23:15]`,跨多處用 `[00:23:15] [01:02:40]`
- 模式 B:`[手寫摘要 p.2 第3點]` / `[簡報 p.7]` / `[email 2026-07-30]`

**標不出來源 = 這條是自己推的。** 處理方式二選一:刪掉,或改列待釐清清單並註明「推論項,待確認」。
絕不能以無來源的形式留在正文。

## 5. 引用原話的時機

需要引用原話的場合:期限、金額、責任歸屬、否決理由、客戶明確承諾。
這些地方**改寫會失真**,直接引號原話 + 時間戳。

其餘一律改寫成書面語。不要整段照抄逐字稿當摘要 —— 那不是摘要。

## 6. 交付前檢核 A(會議記錄,每次必過)

逐條過,有一項不過就回頭補,**不要帶著缺失交付**:

- [ ] 每條決議 / 待辦 / 待議都有來源標註
- [ ] 每條「不執行」的決議都有理由,或已標 `理由未記錄 ⚠️`
- [ ] 每條待辦都有負責人與期限,或已標 `未指派 / 未指定 ⚠️` 且已進待釐清清單
- [ ] 所有期限都是絕對日期,原話保留在括號
- [ ] 沒有任何「應該可以」等級的內容被寫成決議
- [ ] 已檢查後段是否推翻前段的決議(反轉檢查)
- [ ] 講者對應中信心以下都有標註,低信心已進待釐清清單
- [ ] 手寫摘要與逐字稿的衝突都已入差異對照表,未自行裁決
- [ ] 敏感資訊已標 `🔒` 並已詢問是否需要對外版
- [ ] 模式 C:前次待辦每一條都有本次狀態,沒有漏追
- [ ] 待釐清清單已寫在會議記錄內(非獨立檔),每項都有明確的「要問誰、問什麼」
- [ ] 知識萃取節只有一行指標,未把卡片內容塞進會議記錄

## 7. 交付前檢核 B(知識萃取 HTML,僅產製時過)

- [ ] 每張卡片都有分類代號、來源、講述者、信心等級
- [ ] 卡片中的數字 / 參數 / 指令 / 法條是照抄,未經改寫
- [ ] 「踩過的坑」欄位有實際內容才顯示,沒有就整欄不出現(不要印「無」)
- [ ] `ACC` 卡都已標 🔒、加 `locked` class,措辭中性可佐證,無人身評價
- [ ] 沒有為了湊數量而把常識寫成知識點
- [ ] 模式 B 已省略時間軸 SVG,未用假座標硬畫
- [ ] SVG 各段寬度、標記座標依實際數量與時間戳計算,非沿用模板範例值
- [ ] HTML 無任何外部資源請求(CDN / 字型 / 圖片)
- [ ] 萃取中發現的缺漏已回寫會議記錄待釐清清單,且會議記錄版本已推進
