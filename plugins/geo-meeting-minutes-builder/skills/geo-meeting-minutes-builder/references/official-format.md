# 公文體正式會議紀錄(docx)產出規範

使用者指定的正式輸出格式(範本源自「宏碁資訊功能對接架構討論會議紀錄」,
樣式基底存於 `assets/minutes-official-style.docx`)。**會議記錄交付時一律加產
正式版 docx**;MD 版(external/internal template)為工作版並列交付——
時間戳、來源標註、待議、待釐清清單、差異對照**只留在工作版**,不進正式版。

## 產出方式

```powershell
python scripts/build_official_minutes.py <content.json> <輸出.docx>
# 需 python-docx:pip install python-docx
```

content.json schema 見腳本檔頭。檔名:`YYYYMMDD_<會議名>_會議紀錄_正式版_v<n>.docx`。

## 結構(固定順序,不增删)

1. **標題**(置中):計畫/專案全名+第N次+會議名稱,次行「會議紀錄」。
2. **表頭**:會議主題/會議時間/會議地點/與會人員(無名單時寫「詳如簽到表」)。
3. **討論議題**:「提案一、二、…」每案固定「說明:」條列+「決議:」條列。
4. **臨時動議**:無則「臨時動議:無。」;有則條列。
5. **散會。**
6. **追蹤事項表**:項次(中文數字)/追蹤事項/負責單位/完成期限/狀態。
7. **落款**:會議主持人:○○○/會議記錄人:○○○。

## 內容轉寫規則(從工作版 MD 對映)

| 工作版來源 | 正式版去向 | 轉寫規則 |
|---|---|---|
| 議題摘要(各議題) | 提案N「說明:」 | 書面語條列,**刪時間戳與來源標註**;客觀敘述背景與現況 |
| 決議事項(✅/❌/⏸) | 該提案「決議:」 | ❌不執行與⏸延後照寫並附理由/重啟條件;無決議之議題寫「決議:續行研議。」或依實況 |
| 待辦事項(我方+對方合併) | 追蹤事項表 | 事項用動詞開頭書面語;負責單位填**單位名**(非個人;個人名可寫入事項內文如「協請○經理…」) |
| 客戶疑問/待議 | 併入相關提案「說明:」或「決議:」的待確認語句 | 「…需協請討論作法」「…尚待確認」句式 |
| 待釐清清單/差異對照/知識萃取 | **不進正式版** | 留在工作版 MD |

## 格式細則

- **民國紀年**:所有日期一律民國(西元−1911),格式 `115/08/14`;
  時間如「115/08/14 上午 10 時」。
- **項次中文數字**:提案與各條列用「一、二、…」;追蹤事項表項次同。
- **期限**:無明確期限填「未定」(正式版不用「未指定 ⚠️」——⚠️ 是工作版符號)。
- **狀態**:新開追蹤事項一律「進行中」;跨會議(模式 C)時沿用前次表並更新狀態,
  已完成項保留標「已完成」。
- **公文語彙**:條列用「俾利」「協請」「提請討論」「依此辦理」等書面語;
  禁口語(「就是」「然後」)。人名帶職稱(○經理、○專員、○事務官)。
- 字型:中文標楷體、英數 Times New Roman(腳本已內建);標題 16pt 粗體置中、
  本文 13pt、表格 12pt。

## 品質底線

正式版每一條說明/決議/追蹤事項,都必須能對回工作版 MD 的對應條目(工作版有
來源標註可回溯逐字稿);正式版**不得出現工作版沒有的內容**。負責單位與期限
取自實際指派,無則「未定」,不編造。
